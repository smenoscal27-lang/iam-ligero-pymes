Gestor de Identidad y Accesos
Ligero y Seguro para Pymes

Solución integral de autenticación robusta basada en Node.js, Express, SQLite, JWT (HS256) y Doble Factor TOTP con cifrado AES-256-GCM. Diseñada para resolver la persistencia indebida de sesiones en despidos (Offboarding Express) y garantizar trazabilidad inmutable.

ℹ️

¿Por qué estás viendo esta página en GitHub Pages?

GitHub Pages solo hospeda páginas estáticas (HTML/CSS/JS cliente) y no puede ejecutar el motor Node.js ni la base de datos SQLite interactiva. Para usar la aplicación completa con login real, base de datos local y panel administrativo, clona el repositorio e inícialo con npm start en http://localhost:3000.

Arquitectura de Ciberseguridad

Mecanismos Defensivos Implementados

Protección en profundidad frente a vulnerabilidades OWASP Top 10 y cumplimiento estricto de rúbricas institucionales.

⚡

Revocación en Tiempo Real (token_version)

Offboarding Express & Password Invalidation

Los tokens JWT clásicos son persistentes hasta su expiración. Este sistema inyecta un campo numérico token_version en el payload. Al ejecutar Offboarding Express o cambiar la contraseña, se incrementa en base de datos, provocando que cualquier JWT previo sea rechazado de inmediato con HTTP 401/403.

🔐

Doble Factor TOTP con AES-256-GCM

Cifrado en Reposo & Códigos de Respaldo

Flujo seguro en 2 pasos: el secreto Base32 se almacena en SQLite cifrado con AES-256-GCM (enc:v1:<iv>:<tag>:<cipher>). Cuenta con verificación TOTP de 6 dígitos (window: 1), prevención de ataques de replay (last_totp_code) y generación de 8 códigos de respaldo hasheados con SHA-256.

🛡️

Defensas Anti-Enumeración & Timing Attacks

Simulación de bcrypt con Hash Ficticio

Ante correos inexistentes o contraseñas incorrectas, el servidor siempre devuelve el mensaje genérico "Credenciales inválidas" (HTTP 401). Además, se ejecuta una comparación simulada con un hash ficticio para igualar el tiempo de cómputo del algoritmo bcrypt (cost 12), neutralizando ataques por análisis de tiempo de respuesta.

📜

Bitácora de Auditoría Forense (audit_logs)

Trazabilidad JSON Estructurada

Cada evento de seguridad (inicio de sesión, fallos, creación de identidades, offboarding, cambios de contraseña y activación 2FA) se registra en una tabla inmutable de SQLite con estructura JSON detallada que incluye: action, affectedEmail, role, ip y descripción contextual.

Arquitectura RESTful

Catálogo Completo de Endpoints

Rutas modulares montadas sobre Express con cabeceras anti-caché y control de acceso RBAC.

Método Ruta / Endpoint Acceso / RBAC Propósito Funcional
POST /api/auth/login Público Inicio de sesión con anti-enumeración y emisión de JWT HS256.
GET /api/auth/me Token JWT Retorna la identidad y rol del usuario autenticado en sesión.
GET /api/portal/profile Token JWT Consulta de autoservicio de perfil y estado de activación 2FA.
PUT /api/portal/password Token JWT Cambio de contraseña; incrementa token_version cerrando sesiones activas.
POST /api/portal/2fa/setup Token JWT Genera secreto Base32 y lo almacena cifrado en reposo con AES-256-GCM.
POST /api/portal/2fa/verify Token JWT Confirma código TOTP de 6 dígitos, previene replay y emite 8 códigos de respaldo.
GET /api/users Admin Inventario de identidades registradas (excluyendo hashes sensibles).
POST /api/users Admin Alta de usuario; valida unicidad de email y hashea clave con bcrypt cost 12.
PUT /api/users/:id/role Admin Asignación de roles con regla anti-degradación del último Admin.
PUT /api/users/:id/revoke Admin Offboarding Express; bloquea el acceso inmediatamente con HTTP 403.
GET /api/audit-logs Admin Consulta de registros forenses inmutables de auditoría de seguridad.
GET /health Público Healthcheck de conectividad de la base de datos y estado del servicio.
